# Liki 推广伙伴系统 — 评审报告

> 评审日期：2026-09-20
> 评审对象：docs/referral-system-plan.md
> 结论：方案可行，需补 3 个关键实现 + 3 个商业风险缓解

---

## 一、技术评审

### 做对了的

| 设计 | 评价 |
|------|------|
| 两层分销（不做裂变） | 简单，合规，好实现 |
| KOL 50% 佣金率 | 新平台获客有效，文档承认偏高 |
| 付费才能推广 | 筛选真实用户，减少垃圾推广 |
| 终身归因 | KOL 有长尾动力 |
| 体验隔离（用户看不到佣金） | 端用户和 KOL 界面完全分开 |
| 合规条款（禁止"算得准"等） | 降低法律风险 |
| 人工打款 | v1 不需要接支付 API，简单可控 |

### 必须修复（阻塞上线）

#### 1. 自归因没有具体实现

场景：KOL 自己点自己的推广链接 → 注册 → 归因给自己 → 50% 佣金给自己

修复：创建归因时检查 `referrer_user_id != new_user_id`

#### 2. OAuth 用户注册路径遗漏

文档只在邮箱验证里加了 ref 归因，但用户也可能通过 Google/Apple 登录。

修复：把归因逻辑提取为独立函数，在所有用户创建路径调用。

#### 3. 佣金写入失败无重试保障

场景：支付成功 → 履约成功 → 佣金写入失败 → KOL 少拿钱

修复：利用现有 fulfillment_tasks 重试机制，佣金写入失败时标记 failed 让系统自动重试。

### 需要注意（不阻塞）

| 问题 | 说明 | 建议 |
|------|------|------|
| 余额并发竞争 | 两个同时提现可能都通过校验 | 用 SQLite 事务包裹 |
| Cookie 30 天 vs 归因终身 | 合理（cookie 只是初次捕获，DB 记录才是终身） | 代码注释说明 |
| 招商=KOL 同一人 | 不应产生额外 20% | 判断 recruiter_id != kol.user_id |
| 退款处理 | 系统没有退款功能，void 是空话 | 标注 v2 |
| 多币种 | CNY 订单 KOL 用 PayPal 提现需要换算 | v1 人工处理 |

### 架构适配（SQLite + 多库）

| 文档原文 | 调整为 | 原因 |
|----------|--------|------|
| bigserial / bigint ID | TEXT UUID | 统一 ID 体系 |
| FK users(id) | user_id TEXT | referral.db 与 platform.db 分离 |
| FK orders(id) | order_source TEXT + order_id TEXT | 产品各自有 DB |
| decimal(5,2) | REAL（0.50 = 50%） | SQLite 无 DECIMAL |
| timestamptz | TEXT RFC3339 | SQLite |
| 同库事务写佣金 | 最终一致（fulfillment_tasks 重试） | SQLite 不支持跨库事务 |

## 二、商业评审

### 佣金结构分析

¥88 订单的收入分配：

```
场景 A（KOL 直属平台）：
  KOL  50%  = ¥44
  平台 50%  = ¥44

场景 B（招商→KOL→用户）：
  KOL  50%  = ¥44
  招商 20%  = ¥17.6
  平台 30%  = ¥26.4
```

**风险 1：佣金过高，平台利润薄**

50% KOL 佣金在行业里属于极高水平：
- 淘宝客/京东联盟：10-30%
- SaaS 联盟计划：15-30%
- 教育行业：20-40%
- 数字产品：30-50%（因边际成本为零）

50% + 20% = 70% 给分销，平台只留 30%。虽然数字产品边际成本低，但需要覆盖：
- LLM API 调用成本（每次聊天 ¥0.5-2）
- 支付通道费（约 1-3%）
- 服务器/运维
- 客服

**建议：** v1 用 50/20 验证转化率，如果 KOL 数量增长到 50+，降到 40/15。

**风险 2：提现周期不明确**

文档说"人工打款"，但没有说明多久打一次款。
- 如果用户申请了提现，平台拖了一周不打 → 投诉
- 建议：明确 T+7 或每周五统一打款

**风险 3：无最低佣金有效期**

如果一个 KOL 注册后没有任何产出（0 单），他仍然占用一个 code 和 DB 记录。这对系统影响很小，但如果 KOL 数量很大，管理成本上升。

建议：90 天无订单自动标记 inactive（不影响已有归因）。

**风险 4：没有考虑 KOL 挖角/竞争**

如果 KOL 同时推广竞品，拿走了归因用户。因为终身归因，用户就永远跟着那个 KOL。

建议：v1 不用管，但监控"归因集中度"（某个 KOL 占比是否过高）。

## 三、合规评审

### 中国大陆法规

| 法规 | 风险 | 缓解 |
|------|------|------|
| 《反不正当竞争法》 | 分销不能构成传销（三级以上） | 两层分销合规，文档明确"不做裂变" ✅ |
| 《广告法》 | 推广内容不得含有"治愈""改运"等 | 文档已列禁止词 ✅ |
| 《个人信息保护法》 | 推广伙伴能看到被归因用户的个人信息吗 | 设计中不暴露，KOL 只看到统计 ✅ |
| 《电子商务法》 | KOL 是否算"平台内经营者"需要纳税 | 人工打款时保留记录，税务问题 v2 处理 |
| 传销红线 | 入门费 + 拉人头 + 团队计酬 | 付费 ¥88 是产品费不是入门费 ✅，但需要法律意见书 |

### 关键合规风险

**风险 1：传销认定**

中国法律对传销的定义是三个条件同时满足：
1. 交入门费（缴纳费用获得加入资格）
2. 拉人头（发展下线数量作为返利依据）
3. 团队计酬（以下线销售业绩为计酬依据）

分析：
- 条件 1：付费 ¥88 买到的是真实产品（起名服务），不是空壳资格 ✅
- 条件 2：招商收入来自 KOL 的销售业绩，不是拉人头 ✅
- 条件 3：两层分销，且佣金基于实际商品销售 ✅

**结论：大概率合规，但建议在正式运营前获取法律意见书。**

**风险 2：海外用户**

如果用户在海外（USD 支付），适用当地法律（如美国 FTC 关于 MLM 的规定）。建议 v1 限制 CNY 支付用户才能开通分销，v2 再扩展到 USD。

### 海外法规

| 地区 | 法规 | 风险 |
|------|------|------|
| 美国 | FTC MLM 规定 | 两层分销通常合规，但需要收入披露声明 |
| 欧盟 | DSA（数字服务法） | 需要推广内容标识为广告 |
| 新加坡 | 直销法 | 需要牌照（如果算 MLM） |

**建议：v1 限制推广伙伴为中国大陆/香港用户。**

## 四、推广运营评审

### 有效的做法

| 做法 | 评价 |
|------|------|
| 种草文案模板 | 降低 KOL 门槛，统一品牌调性 ✅ |
| 付费体验后推广 | 内容更真实，转化率更高 ✅ |
| 专属链接 | 归因清晰，数据透明 ✅ |

### 需要补充的

**1. 没有 KOL 激励体系（除佣金外）**

50% 佣金是金钱激励。但 top KOL 还需要：
- 等级体系（青铜/白银/黄金，佣金率递增）
- 排行榜（月度/季度，社交荣誉）
- 独家资源（提前体验新功能）

建议 v2 加入，v1 先靠高佣金率吸引。

**2. 没有 KOL 培训内容**

文档有文案模板，但没有：
- 小红书/抖音发布最佳时间
- 目标人群画像（宝妈？留学生？）
- 竞品对比话术
- 转化漏斗优化建议

建议做一个简单的 KOL 培训页面（v1 可以是一个静态页）。

**3. 渠道策略**

文档没有明确主推哪个渠道：
- 小红书：宝妈/命理兴趣人群，图文为主 ✅ 适合
- 抖音：视频号命理博主，流量大但转化低
- YouTube：海外华人，需要英文内容
- 微信朋友圈：私域流量，转化率高但规模小

**建议：v1 主攻小红书（图文模板易做，命理内容不被限流）。**

**4. 落地页转化率**

KOL 发了链接 → 用户点击 → 看到什么？
- 文档没有描述落地页
- 应该是一个带 KOL 归因的定价页（突出 ¥88 + KOL 推荐）
- 不应该是首页（转化率低）

建议：`?ref=xxx` 跳转到带社交证明的定价页，不是通用首页。

## 五、工业实践对标

### 类似系统对比

| 系统 | 佣金率 | 归因模式 | 提现 | 两层？ |
|------|--------|---------|------|--------|
| 淘宝客 | 1-50% | 最后点击 | 自动 | 否 |
| 京东联盟 | 1-20% | 最后点击 | 自动 | 否 |
| Shopify Affiliates | 20% | 30 天 cookie | 自动 | 否 |
| Amazon Associates | 1-10% | 24 小时 cookie | 自动 | 否 |
| Notion Affiliates | 50% 首年 | 90 天 | PayPal | 否 |
| 这个方案 | 50% + 20% | 终身 | 人工 | 是 |

**佣金率偏高但合理**——因为数字产品边际成本为零，且新平台需要高激励。

**终身归因偏激进**——行业标准是 24-90 天 cookie。终身归因对 KOL 很有吸引力，但如果用户在 6 个月后自然回来（不是通过 KOL 链接），平台也要付佣金。建议改为"12 个月归因"作为折中。

## 七、最终结论

方案的商业模型是成立的。两层分销、付费门槛、30 天 cookie 归因（已实现）这套组合拳是合理的。最大的风险不是技术，而是：

1. **合规**：拿到法律意见书之前不要正式推广
2. **利润**：50% 佣金率需要监控 LTV:CAC 比例
3. **执行**：KOL 招募比系统开发更难——先手动找 10 个种子 KOL 验证转化率

技术上没有什么难点，就是标准的 CRUD + 一个 fulfillment hook。核心工作量在前端 Partner Portal。
