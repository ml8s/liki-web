> 受 [BRAND.md](../../BRAND.md) 约束。中英文与简繁各自独立选词，不做互译。本文只记录稳定规则与当前锁定状态；执行计划、评审记录不进入 `docs/`。

## 1. 市场与页面

- 市场：zh-Hans（大陆）、zh-Hant（台港）、en（国际）。
- 页面：首页 + `natal` / `naming` / `liunian` / `hepan` / `divination` / `fengshui` / `huangli`。
- URL slug 上线后不变；`skills` 页已下线。
- 一个页面 × 一个市场只锁定一个 primary + 3–5 个 secondary，避免页内和多页互相蚕食。

## 2. 原则

1. 先定词，再映射到 meta / H2 / FAQ / 正文；不为关键词改 title / H1。
2. 中文分 zh-Hans / zh-Hant，英文单独选词；不做逐字翻译。
3. 词必须有承接：工具、内容区块或 FAQ。没有对应能力时不承诺。
4. 年度词（2026）只做常青页上的更新区块，不新建 URL。
5. 主词尽量与已锁定 title 对齐；不能对齐时，明确由 H2 / meta / FAQ 承接，并接受短期排名折损。

## 5. 页面元素规则

| 元素 | 规则 |
| --- | --- |
| `<title>` / `<h1>` | 已锁定，不因关键词改；全站唯一 |
| `meta description` | primary + 2 个 secondary；中文 ≤ 80 字，英文 ≤ 155 字符 |
| `<h2>` | 承载 secondary 词族；常规页 3–6 个，hub 页可更多 |
| `<h3>` / 卡片 / FAQ | 承载长尾与问句意图 |
| 内链 | 锚文本使用目标页 primary；hub 页向场景页分发 |
| canonical / hreflang | 每页自指；三语 alternate 保持构建输出 |
| 结构化数据 | 场景页 `Service` + `BreadcrumbList` + `FAQPage`；legal 页 `AboutPage` / `ContactPage` / `WebPage` |

## 7. 数据与复检

- 数据源：Google Search Console（`sc-domain:liki.hk`）、Bing Webmaster、Google / Bing / Baidu Suggest。
- 工具：`seo` CLI（`report` / `page` / `crawl` / `data`）；付费量级需 DataForSEO 或 Ahrefs key，暂不接入。
- 判定：新页面收录 ≤ 4 周；目标词进入前 20 后按 CTR 迭代 meta/H2/FAQ；2–4 周复盘一次。
- 年度词在常青页上更新，不新建 URL。

## 8. 慎用词与意图边界

- `择日` 单独搜索被小说《择日飞升》污染，不用作 primary；用 `黄历`、`择吉`、`吉日查询`。
- `算卦` 热度高但口语化，与专业定位有张力；只放 FAQ，不进 meta / H1。
- `tai sui`、`annual fortune`、`life gua`、`tong shu` 有歧义；必须带语境，如 `tai sui 2026`、`annual fortune chart`、`kua number`。
- `chinese name generator` / `起名生成器` 由 naming 页承接：免费喜用神 → AI 起名生成器 CTA 到 Liki Chat；不承诺免费生成。
- `what is my chinese name` 是翻译/取名意图，页面不做，不做主词。
- `东四命 / 西四命` 适合 FAQ / 解释块，不做页面 primary。
