# Liki App UX / 交互设计（Phase 1）

- 版本：v1.0
- 关联：`docs/platform-fs.md`（功能规格，后端契约以它为准）、`docs/frontend/README.md`（前端架构）
- 范围：登录后 Vue 3 SPA（`/app`）的交互设计，只覆盖新平台；legacy 页面不动

## 1. 用户任务地图（JTBD）

| 用户场景 | 任务 | 成功标准 |
|---|---|---|
| 好奇、未付费 | 免费建一个档案，看到这个人的盘 | 建档 ≤3 步；排盘异步完成后盘面可见，全程不出现"购买"阻断 |
| 看到盘后想深入 | 付费解锁 Chat 自由对话 | 从盘面 CTA 到支付完成 ≤3 步；返回后权益自动刷新 |
| 已购、有疑问 | 围绕某人自由提问 | 选档案 + skill → 会话自动带上该人信息，无需重复交代生辰 |
| 会话中追问/中断 | 连续对话、停止、刷新恢复 | 流式稳定、可停止、URL 直达可恢复、盘面卡回放不丢 |

## 2. 信息架构

```
/app（登录后）
├── dashboard     工作台：主 CTA"继续上次咨询"（最近会话直达）+ 档案概览 + 购买状态
├── profiles      档案列表（多档案：本人/家人/朋友）
│   ├── new       建档表单（免费）
│   └── :id       档案详情：基本信息 + 三盘展示 + 解读入口
├── chat          会话中心：档案选择器 + skill 选择 + 会话列表
│   └── :sessionId 会话：SSE 对话 + 盘面卡回放
├── orders        订单（已有）
├── account       账户 + 会话管理（补齐）
└── reports       预留（不动）
```

**关键取舍**：
- **盘面归档案**，不嵌在 chat 页（排盘是"档案的属性"，不是"会话的前置步骤"）；
- **chat 页是"选人 → 选领域 → 会话"**，一个入口完成；
- 4 个内部 skill 永远是"能力选择"，不是商品；商品只有一个购买入口（档案详情/权益态 CTA）。

## 3. 页面交互设计

### 3.1 `/app/profiles` 档案列表
- 顶部：标题 + "新建档案"主按钮
- 列表项：称呼、关系标签、三盘状态徽标（`ready` 正常 / `pending` 计算中 / `failed` 可重试 / `skipped` 待定盘）、最近使用排序
- 状态矩阵：`loading`（骨架）→ `empty`（空引导"创建第一个档案"）→ `list` / `error`（重试）
- 交互：点击进详情；删除走确认弹窗（软删，提示 30 天恢复窗口）

### 3.2 `/app/profiles/new` 建档表单（渐进式，用户价值优先）
- **第一屏（只有 2 项，30 秒内点出）**：称呼 + 出生日期（公历/农历切换）。性别/时间/出生地全部进第二步展开。
- **第二步（展开）**：出生时间、性别、出生地（城市）、关系标签、备注。
- **出生时间**：
  - 精确时刻 `HH:mm` 输入（默认）→ `birth_time_known=known`
  - "只知道时辰" → 十二时辰选择 → `approximate`
  - "时间不确定" → `unknown`，文案**无压力**："不确定也能算，之后可对话定盘"（不让用户觉得被卡住）
  - 出生地仅与"精确时刻"组合时走**路 A 真太阳时校正**，UI 实时提示"已选择城市，将做真太阳时修正"
- 状态：`idle → validating → submitting → 成功(跳详情) / 字段内联错误`
- 提交后立即跳 `/app/profiles/:id`，**渐进呈现盘面**：先出八字，紫微/八宅逐个补齐（见 3.3），不干等骨架屏

### 3.3 `/app/profiles/:id` 档案详情
- 区块：①基本信息（称呼/关系/出生信息摘要，可编辑）②盘面 ③解读入口
- **盘面**（`pan_status` 驱动）：
  - `pending/recomputing` → 渐进呈现：先出八字，紫微/八宅"计算中…"逐个补齐，不整体干等
  - `ready` → 三盘卡（八字/紫微/八宅，可折叠）
  - `partial` → 已就绪子项正常显示 + 缺失子项"排盘中/失败可重试"
  - `failed` → 错误态 + "重新排盘"
  - `skipped` → 提示"出生时间不确定"，CTA 引导去对话定盘
- **人话摘要（免费可读性）**：每盘顶部给一行确定性摘要（如"八字：火旺，喜水木"），由**确定性引擎**出，不依赖付费 agent——让免费用户"看懂 1%"而不是面对符号乱码
- **解读入口**（权益态）：
  - 未购 → 一个"解锁 Chat"CTA（`ProductPurchaseCard` 展开）
  - 已购 → "开始解读" → **默认推荐 skill**（档案排了 bazi/ziwei → 默认八字，可改）→ 建会话
- 编辑出生信息 → 乐观锁（冲突 409 时提示刷新重试）

### 3.4 `/app/chat` 会话中心
- 顶部：档案选择器（下拉/卡片，默认最近使用）+ skill 选择（4 卡，**默认推荐**档案对应的 skill）
- 未选档案 → 引导去建档
- 档案 `pan_status` 不满足建会话（`pending/failed`）→ skill 卡禁用 + 说明（6.7 矩阵）
- 会话列表：标题（档案称呼 · 领域）、最后消息时间、`loading/empty(引导)/list/error`
- 建会话 → 跳转 `/app/chat/:sessionId`

### 3.5 `/app/chat/:sessionId` 会话
- 头部：返回 + 档案称呼 · 领域 + 盘面开关（盘面走前端 RPC 直连，同档案页）
- 消息流：`user / assistant文本 / system_profile 档案卡`
- 首条固定为 `system_profile`（系统写入用户信息摘要，只读展示）
- 流式：`thinking → phase → text-delta` → `done` 替换占位
- 滚动：sticky-to-bottom；用户上滚即暂停跟随
- 停止：流式中 Composer 变"停止"；停止后重拉权威消息
- 发送：Enter 发送 / Shift+Enter 换行 / 发送中禁重复
- 刷新/直达 URL → 恢复会话，档案卡从消息回放

### 3.6 支付返回
- 返回 `/app/chat?status=paid&order_id=…`
- `paid` → 顶部提示"支付已确认，正在开通 Liki Chat…" → 轮询权益 → 成功"已开通" → **直接进入解读路径**（建会话并跳转，或聚焦档案详情"开始解读"），不让用户回流再找 → 清理 URL query
- `unpaid` → 提示"支付未完成"，不阻断浏览订单

### 3.7 `/app/account`
- 邮箱、登录态
- 当前 session（标注"当前设备"）+ 其他 active sessions（可 revoke）
- 登出、注销（合规强删入口）

## 4. 关键交互决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 盘面归属 | 档案详情，不嵌 chat 页 | FS：盘面是档案属性 |
| 建档表单 | 第一屏 2 项（称呼+日期），时间/性别/地点第二步 | V1：30 秒点出第一屏 |
| 盘面呈现 | 渐进（先八字）+ 每盘人话摘要 | V2/V3：即时满足 + 免费可读 |
| 会话创建门槛 | 按 `pan_status` 矩阵放行/拦截 | FS 6.7 |
| 注入展示 | `system_profile` 首条消息（系统写入用户信息摘要） | FS：档案=用户信息 |
| 付费门 | 档案详情单 CTA，skill 卡永不付费 | FS 唯一 SKU |
| 支付返回 | 成功后直接进解读路径 | V4：回流损耗最小化 |
| 老用户路径 | dashboard"继续上次咨询"主 CTA | V5 |
| skill 选择 | 默认推荐档案对应 skill | V6 |
| 滚动 | sticky-to-bottom，用户上滚暂停 | 修复现有无条件滚动 |
| 移动端 | 建档/盘面/会话 M1 起适配 | V7：付费发生在手机 |

## 5. 设计方向与 tokens

**方向**：东方工作台 —— 信息架构为主（盘面是数据面板），墨/纸中性 + 品牌紫金；不沿用现有通用外壳（深灰 + Element Plus 蓝），也不落入"科技紫渐变 / 花哨玄学风"。

**定位四问**：叙事角色=工具台（盘面是 hero 数据时刻）；观看距离=桌面+移动；视觉温度=专业、庄重、有分寸；容量=盘面高密度 → 分组网格 + 可折叠。

| token | 取值 |
|---|---|
| 品牌主色 | `#6d5acf`（紫）；变体用 oklch 同色相推导：hover `#5a47c0`、light tint `#eeeafc`、border `#d9d2f5` |
| 点缀金 | `#c9a45e`（古董金）：已开通 / 盘面 hero / 宫格分隔 |
| 墨 | `#232733`：主文字 + 顶栏（深墨） |
| 纸 | `#faf9f7`：页面底（暖纸白） |
| 中性 | 次级 `#5b6472` / 三级 `#9aa3af` / 分隔 `#e3e1dc` |
| 五行标签色 | 青 `#3b82a0` 火 `#c25a4e` 土 `#b8915a` 金 `#c9a45e` 水 `#4a5d8a`（仅盘面分组标签） |
| 语义色 | 成功 `#67c23a` / 警告 `#e6a23c` / 危险 `#f56c6c`（Element Plus 默认） |
| 字体 | 品牌/标题：宋体栈 `"Songti SC","Noto Serif CJK SC",serif`；正文：system-ui 栈 |
| 字号 | h1 28/700(serif) / 页面标题 22 / 正文 16 / meta 13 |
| 间距 | 8pt 网格；卡片 padding 16；区块 32 |
| 圆角 | 大卡 12px / 控件 6px（Element Plus 默认）/ pill 999 |
| 动效 | 骨架 shimmer + 过渡 160–240ms；盘面 ready 200ms fade-in；无装饰动画 |
| 盘面 | 顶部 2px 金线 + 大留白；分组宫格（金分隔线 + 五行标签），Tufte 式对齐；不引入新图表库 |

**Element Plus 集成**：覆盖 `--el-color-primary: #6d5acf` + 派生 shades，其余组件默认不变——不 fight 框架，不被框架绑架。

## 6. 状态矩阵汇总

| 页面/组件 | 状态 |
|---|---|
| 档案列表 | loading / empty / list / error / 删除确认 |
| 建档表单 | idle / validating / submitting / 内联错误 |
| 档案详情 | loading / ready(三盘) / partial / failed(重试) / skipped(待定盘) / 编辑冲突 409 |
| 盘面轮询 | 轮询中 / ready / 超时(提示刷新) |
| 会话中心 | 未选档案 / 档案门槛不满足 / loading / empty / list / error |
| SkillCard | disabled(权益或档案门槛) / enabled / starting |
| 会话 | loading / empty / streaming(thinking·phase·delta·chart) / done / error / stopped / reloading |
| 支付返回 | verifying / confirmed / unpaid |
| 账户 | loading / loaded / revoke pending / error |

## 7. 验收标准

- 新用户：第一屏 30 秒内点出，建档后立即看到八字，紫微/八宅渐进补齐；全程无购买阻断
- 每盘有一行确定性"人话摘要"，免费用户能看懂 1%
- 已购用户从档案到进入会话 ≤3 步，无需重复交代生辰；skill 默认推荐
- 老用户：打开 dashboard 一次点击"继续上次咨询"进会话
- 支付返回成功后直接进入解读路径，不回流
- 移动端建档/盘面/会话全流程可用（M1 起）
- 任一步中断（刷新/停止/断网/引擎故障）可恢复且盘面不丢
- 4 个 skill 永不呈现为 4 个商品
- 会话首条 `system_profile` 档案卡可回放
