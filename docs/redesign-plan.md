# Liki 产品级重新规划（Redesign Plan）

- 版本：v1.0
- 状态：规划稿（待评审实施）
- 方法：18-skill 前端设计套件（frontend-design / interaction-design / ux-writing / better-*）
- 范围：主页（Astro 3 locale）+ App（Vue），**不含** legacy naming/mingshu/hepan

## 1. 现状诊断

| 问题 | 根因 |
|---|---|
| 主页像"skill 开发者页"（`npx skills add` 为主） | 定位是开发者工具，非 C 端用户产品 |
| 主页 wood/石 ↔ App 墨/紫 两套视觉 | 两套设计系统，品牌断裂 |
| App 像后台（功能罗列） | 缺用户旅程、价值叙事、空态引导 |
| 四服务是"能力列表" | 没转成"用户任务" |
| 免费排盘钩子只藏在 App 档案页 | 主页没有转化桥 |

**目标**：一套品牌（墨纸紫金+宋体），主页=用户着陆页（转化桥），App=命理工作台（旅程完整），两个端点产品级统一。

## 2. 产品定位与品牌系统（frontend-design）

**定位一句话**：懂命理，用灵机——专业命理师的确定性排盘与解读平台。

**品牌三支柱（UI 上持续传达）**：
1. **确定性**：排盘由引擎计算（31 RPC、数据锚点），非 LLM 发挥
2. **专业**：按命理师标准构建，断语走真值表可溯源
3. **免费入口**：建档 + 排盘免费，解读解锁

**品牌记忆点**：宋体标题字 + 墨纸紫金 + slogan「懂命理，用灵机」（全触点一致）。

## 3. 信息架构

```
主页（Astro，3 locale）
├── /（用户着陆页）  Hero → 免费排盘钩子 → 四服务 → 信任段 → 步骤 → CTA → footer
├── /skills（开发者 skill 页）  原首页内容迁移（npx 安装/agent-skills 发现/llms.txt）
├── /about /contact /privacy /terms /404
App（Vue，平台）
├── /login
├── /（工作台）     继续上次 + 首访引导 + 概览
├── /profiles(+new/:id)
├── /chat(+/:id)
├── /orders /account
```

**关键决策**：
- **主页 = C 端着陆页**（新），**原开发者 skill 页整体迁移到 `/skills`**（不删除，保留安装命令/发现协议/llms.txt）。
- App 采用**左侧边栏导航**（桌面）+ **底部 tab**（移动），替代当前顶部导航。

## 5. 主页逐页规划

### 5.1 首页 `/`
**功能**：免费排盘轻交互（出生信息 → 引擎排盘预览；未登录则收集后引导登录续算）；四服务详情；信任锚点；登录/建档 CTA。

**Wireframe（区块自上而下）**：
```
┌ Header：品牌(Liki·灵机) + slogan tagline + 导航(首页/服务/关于) + 登录 ┐
│ Hero：slogan 大标题（宋体）+ 副标"确定性排盘 · 专业解读"
│       双 CTA [免费排盘 · primary紫] [了解更多 · ghost]                │
│ 免费排盘卡：出生信息(日期/时间/性别/城市) → 排盘预览按钮
│       未登录 → 按钮变"登录后免费排盘"                                  │
│ 四服务宫格：起名 / 八字 / 问卦 / 风水（各卡片带"去体验"→/app）        │
│ 信任横幅（墨底金字）：31 引擎锚点 · 597 断语真值表 · 可验证            │
│ 步骤横条：①建档 ②免费看盘 ③解锁 ④自由对话                          │

│ Footer：slogan + 链接                                                 │

```

**文案（ux-writing）**：
- Hero 副标：`确定性排盘，专业命理师标准，结论可验证。`
- 免费排盘卡标题：`免费排盘，看看你的命盘`
- 免费排盘按钮：`开始免费排盘`
- 未登录：`登录后可查看完整命盘并开启解读`
- 四服务卡：`起名——依八字用神取名` / `八字——命盘·大运·流年` / `问卦——六爻·奇门断事` / `风水——八宅·玄空布局`
- 信任卡：`31 项引擎数据锚点` / `597 条断语真值表` / `结论可验证、可溯源`

**布局**：1200 容器；Hero 全宽居中；移动端单列（免费排盘卡置顶于 Hero 下）。

## 9. 用户流程系统分析与交互优化（interaction-design）

### 9.1 核心流程（flow 地图）

**F1 新访客转化漏斗**
```
主页(着陆) → 免费排盘钩子 → 注册/登录 → 建档 → 免费排盘(三盘)
→ 解锁 Chat → 支付 → 权益确认 → 建会话 → agent 解读
```
**F2 已购回访**：登录 → 工作台(继续上次) → 会话
**F3 免费看盘**：建档 → 三盘预览 →（未购）解锁
**F4 账户合规**：订单 / 会话管理 / 注销

### 9.2 F1 逐步骤系统分析

| 步骤 | 用户动作 | 系统响应 | 摩擦点 | 优化 |
|---|---|---|---|---|
| 着陆 | 看到 slogan+免费排盘 | Hero + 免费排盘卡 | 未登录不能续算 | **草稿续算**：主页输入出生信息→预览→登录后自动续算排盘 |
| 登录 | 邮箱验证码 | 发码/验证 | 邮箱门槛 | 保留（无 OAuth，合规）；价值点展示 |
| 建档 | 填出生信息 | 渐进表单 | "时间不确定"恐惧 | 文案"不确定也能算，可对话定盘" + 性别默认女 |
| 免费排盘 | 看三盘 | 引擎 RPC | 之前只八字 | 三盘 tab + 全面数据（§6.4） |
| 解锁 | 点解锁→支付 | checkout→provider | 支付返回等待 | 轮询权益 + 直达解读（已做，commerce store） |
| 解读 | 对话 | agent | — | 首条档案卡 + 自动注入（已做） |

### 9.3 系统级交互原则

1. **流程连续性**：主页出生信息草稿 → 登录续算（跨站点续流）
2. **状态透明**：排盘/解读 loading 有 phase 文案 + 骨架
3. **中断可恢复**：支付返回、会话刷新、排盘失败重试（均已具备，保持）
4. **反馈即时**：按钮 pending、成功轻提示（ElMessage）、错误内联
